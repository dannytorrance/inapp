Case Study · New Product Channel

Building InApp, the fourth channel of ALFA.

ALFA already reaches users through three channels — SMS, Email and Push Notifications. InApp is the fourth: messaging delivered directly inside the product itself, configured on top of ALFA's existing, mature design system (v5.0).

This case study walks through the Molecules layer built for InApp: the components that let a channel this dense — sidebars, dialogs, tables, settings panels.

01Overview

A configuration surface, not a marketing surface.

In plain terms: InApp is a template configurator. It's where operators build the messages, banners and guided flows that appear directly inside the product — picking the layout, filling in the content, setting who sees it and when, then publishing it as a template.

SMS, Email and Push Notifications all share one trait: the operator configures the message, and it leaves the product. InApp breaks that pattern — the message stays inside the product, so the tooling to build it has to live there too: dense sidebars full of margin, padding, border and shadow controls; dialogs for creating templates; tables for managing data sources; popovers for fine-tuning a single variable.

02Problem

Design challenge

InApp introduced a fundamentally different configuration experience into an existing system built around simpler outbound channels. The challenge was to support a much denser editor without creating a separate visual or interaction language.

—Scope

Interactive user flows mapped out the complete InApp workflow: from onboarding and template setup through multi-screen editing, settings management, and finalization. Each flow has a corresponding interactive prototype that demonstrates panel switching, state transitions, and real-world interactions — these prototypes served as the source of truth for the frontend development team.

03The System

Nine molecule groups, one governed catalog.

The Molecules layer sits between raw atoms (buttons, inputs, icons) and full patterns (screens, flows). Every control an operator touches while configuring InApp — from picking an identity to filtering a data table — is documented here as a named, versioned specimen, built on the same ALFA foundations already used by SMS, Email and Push Notifications.

InApp's whole system is layered this way — atoms → molecules → organisms → templates → pages — following Brad Frost's atomic design methodology.

05Outcomes

From atomic components to a scalable design system.

The system follows a strict hierarchical composition: atomic components (buttons, inputs, icons) → molecules → organisms (configurable sidebars, multi-step dialogs, data tables, property inspectors) → full screens. This structure was applied across a complete InApp editor: multiple screens for template registration, editing, settings and preview, plus interactive prototypes demonstrating panel switching and real-world interactions. Every surface, from the simplest input to the densest data table, is assembled from the same atomic building blocks.

The InApp channel was designed as a scalable extension of ALFA rather than a standalone product. The resulting system provides a shared foundation for template creation, responsive behaviour and future channel expansion.
