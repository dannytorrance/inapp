Case Study · New Product Channel

Building InApp, the fourth channel of ALFA.

ALFA already reaches users through three channels — SMS, Email and Push Notifications. InApp is the fourth: messaging delivered directly inside the product itself, configured on top of ALFA's existing, mature design system (v5.0).

This case study walks through the Molecules layer built for InApp: the components that let a channel this dense — sidebars, dialogs, tables, settings panels — stay a first-class citizen of the same system as SMS, Email and Push.

01Overview

A configuration surface, not a marketing surface.

In plain terms: InApp is a template configurator. It's where operators build the messages, banners and guided flows that appear directly inside the product — picking the layout, filling in the content, setting who sees it and when, then publishing it as a template.

SMS, Email and Push all share one trait: the operator configures the message, and it leaves the product. InApp breaks that pattern — the message stays inside the product, so the tooling to build it has to live there too: dense sidebars full of margin, padding, border and shadow controls; dialogs for creating templates; tables for managing data sources; popovers for fine-tuning a single variable.

Reading the flow the file itself lays out — Main Menu → Template Registration → an editor with a layout picker, a message-header form and per-breakpoint settings — InApp exists so a non-developer can register an integration ("identity"), then assemble, preview and publish a localized in-app template without writing code. The registration step alone (Registration of Identity) suggests this was built for a multi-tenant setup: several apps or environments, each getting its own identity, sharing one configurator.

02Problem

No off-the-shelf channel looks like this.

SMS, Email and Push each ship one thing: a message. InApp has to ship an entire embedded control surface — property inspectors, data tables, multi-step dialogs — none of which the three earlier channels ever needed. Reusing ALFA's existing components only went so far: a single "Sidebar Content Row" alone grew 33 parallel versions as margin, padding, border and radius controls got adapted for InApp's density, old and new flavors still standing side by side. Dialogs reached 23 versions before header, footer and button-area logic were unified across them.

What likely got reused from ALFA: the basic input primitives — text fields, dropdowns, checkboxes, the dialog frame, the table shell. What InApp needed on top, that no earlier channel did: a layout tile-picker for choosing header/footer/sidebar structure, a message-header form (subject, priority, schedule, icon), live data-source and variable binding, and typography settings scoped per responsive breakpoint with a device-switchable preview. That's a property-inspector's worth of new surface area layered onto old primitives — a plausible source of the "old vs. new" duplication sitting side by side in the file.

03The System

Nine molecule groups, one governed catalog.

The Molecules layer sits between raw atoms (buttons, inputs, icons) and full patterns (screens, flows). Every control an operator touches while configuring InApp — from picking an identity to filtering a data table — is documented here as a named, versioned specimen, built on the same ALFA foundations already used by SMS, Email and Push.

InApp's whole system is layered this way — atoms → molecules → organisms → templates → pages — following Brad Frost's atomic design methodology. This case study only zooms into one rung of that ladder.

04Design Tokens

Borrowed foundations, channel-specific molecules.

InApp doesn't define its own color, spacing or radius scale — it draws directly from ALFA's platform tokens, the same ones already running SMS, Email and Push. What's new at the Molecules layer is how densely those tokens get composed, not what the tokens themselves are.

05Outcomes

InApp joined the system — instead of forking it.

~158 documented states across 9 molecule groups mean an operator sees the same margin control, the same dialog shell, the same table row whether they're inside InApp, SMS, Email or Push. That consistency is the actual deliverable — not a single screen, but a shared vocabulary a fourth channel could plug into.
